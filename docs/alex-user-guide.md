# Alex 操作手册

Alex 把你的企业资料、客户证据和任务进度保存在当前工作空间。第一次使用时由你说明产品、目标市场和希望寻找的客户类型；这些内容不由项目预设。当前部署对应一位用户或一家企业的工作空间。

运行方式见[部署指南](alex-deployment.md)，不同 Agent 入口见[网关与 Hermes 对照](alex-gateways.md)。默认打开 `http://127.0.0.1:3210`。

## 第一次交代需求

在“与 Alex 继续聊”中介绍实际业务，再点“发送”。例如说明生产哪些产品、希望进入哪个市场、客户应是什么类型。行业与国家由使用者自行填写，不是默认获客条件。

Alex 会读取已有企业资料、记忆和本会话前文，询问缺少的信息，并给出研究提案。可以继续回复以补齐要求；检查提案中的产品、市场、客户类型、数量和来源路线后，点“执行此方案”才启动研究。发送聊天消息本身不会启动获客或外发。

一次性的任务要求与长期企业资料有不同用途。要改变长期资料时明确说要长期记住，可在“我的业务记忆 → 编辑”中核对和纠正。资料带历史版本，后续任务继续读取。

历史会话下拉框可读回以前的交流；“新会话 ＋”开启新的交流记录，仍保留企业资料、客户与任务。用户消息会持久保存；模型未配置时仍保存你的消息并报告不可用，不生成虚假 Alex 答复。刷新页面或重启后可以选择同一会话继续。

模型需要安全配置 `ALEX_LLM_API_KEY`。没有模型或模型请求失败时，界面应明确显示不可用；它不会自行假设一个行业、国家或客户类型。你仍可管理资料和客户，或使用下一节的明确条件与官网核验。

## 用真实来源研究

在“直接填写筛选条件 / 核验官网”中选择适合的路线：

| 路线 | 需要提供 | 实际执行 |
| --- | --- | --- |
| 搜索新客户 | 产品、目标市场、客户类型、数量；可加排除关键词 | 浏览器打开真实搜索来源，提取候选外链，再访问公司官网保存证据 |
| 核验公司官网 | 已知公司的实际 HTTP(S) 官网地址 | 浏览器直接访问所给页面，核验公开信息，并补充已有档案或建立待复核记录 |

单任务最多要求 20 家公司。关键词约束作用于来源：官网正文出现排除关键词时，候选被拒绝；缺少包含关键词的证据时不能判为已匹配。自由备注只存档，不能代替已经实现的筛选字段。

搜索新客户会排除已存客户，包括归档客户；官网核验路线允许补充旧客户的证据。相同网站下出现不同公司名称时可能需要人工身份核验，系统不按同名、公共邮箱或模糊集团关系强行合并。

没有模型时，成功抽取的官网记录标记为待复核。这说明来源已取得，不说明其产品、所在地和客户类型已经满足你的条件。目标销售市场也不会被自动写成公司的所在地。

搜索页面不可用、官网拒绝访问、验证码、权限不足或数量不足时，查看任务的真实状态与失败地址。`partial` 是部分结果，`blocked` 是来源阻断，`unavailable` 是所需能力当前不可用。任务完成也要检查实际数量、匹配数量和待复核数量；空邮箱和电话表示未观察到，系统不会猜测补齐。

目前没有 Google Maps 专用 Places 适配器或海关企业交易数据接口。浏览器能打开某个网站，不等于项目已获得该来源的结构化查询能力或授权。

## 暂停、继续与人工接管

任务列表保存步骤、事件和检查点。需要中止研究时点“暂停”；以后继续同一个任务。重启服务后，先前执行中的任务转为暂停，继续会复用已完成网址和客户 ID。多个研究任务串行使用同一个浏览器。

“接管浏览器”会暂停进行中的任务。接管后可在画面中点击、输入、按键和滚动，也可以访问一个实际网址；这些操作作用于 Agent 使用的同一 Chromium 会话。处理完允许的登录或人工核验后，点“交还 Alex”，再到任务列表继续。

交还不会自动替你执行所有暂停任务。取消后的任务不能恢复；创建新任务时仍会查询已有客户与归档身份。Agent 不会在人工接管期间抢回控制权。

浏览器面向公开 HTTP(S) 来源，拒绝内网地址。Agent 浏览器请求只允许 GET/HEAD；需要写入网页、登录提交或处理账号时由你接管。项目不提供验证码绕过。

## 客户、证据与存档

客户卡片展示官网、公开邮箱和电话；打开详情核对来源 URL、获取时间、页面标题和原文摘录。联系方式必须来自实际页面观察。网站内容是来源材料，不能授权 Agent 外发消息或改变权限。

归档客户会从默认列表隐藏，仍参加查重；勾选“包含已归档客户”可以读回。补充官网联系页时，如果实际页面明确提到既有公司名称，可以更新同一档案；身份存在冲突时保留核验问题。

“导出 CSV”包含客户 ID、官网、公开联系方式和来源 URL。它适合在表格中继续工作，但不是完整备份：资料历史、任务检查点、审批记录和会话需要业务备份保存。

## 草稿和人工复核

在客户操作中准备开发信草稿。配置模型后，Alex 根据已存企业资料和该客户的实际来源材料生成内容；缺失的事实应省略或显示待补充项，不应出现虚构认证、价格、客户关系或业绩。

在“草稿”中检查完整主题与正文，再批准或拒绝。审批绑定具体内容并留下记录。当前版本没有真实邮件、WhatsApp 或 CRM 发送能力；批准草稿只保存复核结果。Hermes 和 MCP 工具也不能替用户审批。

## 备份与恢复

在“备份 → 立即创建备份”创建业务数据库的一致快照。命令行也可以执行：

```bash
npm run backup
```

备份保存资料、客户、记忆、证据、任务和草稿历史；新增持久会话也属于业务数据库。清单记录文件校验值。浏览器 Cookie、本机 API token 和模型密钥不进入业务备份，恢复后需要重新配置。备份存放位置见工作空间设置。

默认副本在本机。同一硬盘上的副本无法应对设备损坏；将生成的完整备份目录另外保存到可信的另一设备或备份系统。

恢复由维护者在命令行执行，先停止旧服务，保留原数据，目标必须是新建空目录：

```bash
node scripts/alex-backup.mjs restore <完整备份目录> <新的空数据目录>
```

恢复程序校验 manifest、文件哈希和数据库完整性，拒绝覆盖已有数据。把 `ALEX_DATA_DIR` 改为新目录，重新启动，核对客户 ID、证据、企业资料、会话和任务；再重新绑定模型配置和 Hermes/MCP 的 token 文件路径。不要修改校验值强行恢复，也不要直接复制正在运行的 SQLite 主文件。

## 区分演示与真实获客

仓库的工作台截图、GIF 和自动化测试可以使用标注的受控 fixture 展示操作。这些记录不计为真实客户。

真实验收要看到实际公网公司、可打开的来源、观察时间和正文证据，并确认重复研究、重启与备份恢复后仍保留同一档案。本轮环境状态见[验收记录](alex-acceptance.md)。公网出口或模型仍不可用时，即使工程测试通过，也不能据此宣称真实获客成功。
